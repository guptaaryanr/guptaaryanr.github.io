01

Inverse problems · PDE simulation · Devito

WaveSleuth-Devito

Inverse Wave Playground v1.0

2026

I built WaveSleuth to learn Devito by implementing an inverse problem from start to finish. A 2D acoustic model generates traces from a hidden medium, and the inversion tries to reconstruct it from sparse observations. The v1 release adds blind challenges, scoring, and checks that the results can be reproduced.

Inside it
Several acquisition geometries, a real Devito forward model, simple inversion baselines, blind challenges, active sensing, uncertainty summaries, scoring, and release checks.
Scope
A 2D constant-density acoustic testbed, not field-scale seismic imaging. The inversions are deliberately constrained so experiments can be reproduced and inspected.
1 hidden medium→2 sparse traces→3 invert→4 reconstruct + score

This is the v1.0 workflow. The small number of sources and receivers leaves room for ambiguous reconstructions.

02

Nonlinear dynamics · Scientific computing · Trajectory analysis

Trajectory-Only Structural Regime Detection

2026

The detector gets full-state trajectories and the order of a parameter sweep, but no equations, regime labels, or transition definitions. I wanted to see whether it could still identify a structural boundary.

What it gets
Trajectories and the order of the parameter sweep. From those it builds a fixed set of indicators, a structural score, and an extracted boundary.
How I checked it
I defined the qualitative transitions separately and withheld them until evaluation. In both deterministic benchmark families, the boundary detected from multivariate/full-state trajectories appeared earlier. That is a result on two systems, not a general result about every dynamical system.

03

Scientific ML evaluation · Thermodynamics

ThermoBench-Consist v1.0

2025

A GNN surrogate for vapor–liquid equilibrium looked adequate by ordinary prediction error, then failed inside a solver because its learned surface and derivatives were unreliable. I built ThermoBench to test physical consistency before a surrogate reaches that stage. The current benchmark targets pure-fluid equations of state; the motivating GNN problem involved a mixture.

Basic test
C1–C4 check monotonicity, mechanical stability, phase consistency, and sound speed before the surrogate is used in a solver.
The catch
Critical and spinodal regions need guardrails. Without them, the diagnostic starts flagging perfectly reasonable behavior as a failure.

Diagnostic example / reference and deliberately inconsistent adapters

C1ρ should rise with pmonotonicity
C2κT > 0mechanical stability
C3Clapeyron slopephase consistency
C4a² > 0speed of sound
reference adapterPASS · PASS · PASS · PASS
deliberately inconsistent surrogateFAIL · PASS · FAIL · FAIL

These are the reference and deliberately inconsistent test cases; they are not mixture-VLE validation. The pure-fluid benchmark uses CO₂ and N₂ grids, with exclusions near critical and spinodal regions.

Costgate

CI cost regression gate for LLM inference

2026

A code change can leave an LLM pipeline’s answers unchanged while raising the cost per valid answer. Costgate compares a candidate run against a baseline in CI and checks it against a policy.

Compared
Baseline and candidate runs over the same suite. It looks at cost per valid success, token use, task success, latency, repeat variability, and explicit thresholds.
What it produces
A YAML policy, inspectable run artifacts, and a pass, warn, or fail verdict.

For reproducible examples, CostRegBench runs controlled regression scenarios and checks the resulting pass, warn, or fail against the expected outcome. These are fixture-based tests, not measurements of an external production LLM.
